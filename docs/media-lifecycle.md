# 媒体删除、清理与审计

面向部署管理员。界面上的用户操作说明见[记录、照片与相册](user-guide/records.md)。

## 状态与文件

`Media.status` 只有两个值：

- `ACTIVE`：正常显示，接口可读取。
- `DELETED`：在回收站里。原图、缩略图、展示图和视频播放版**全部保留**，普通页面和媒体接口不再返回。

删除照片不会降低原图质量，也不会把原图改写成缩略图。所有变体都由 `Media.storageDriver` 记录上传时的存储后端，清理时按这个后端执行，因此本地存储和 OSS 的行为一致。

## 软删除（界面上的“删除”）

删除一张照片时：

1. `Media.status` 改为 `DELETED`，记录 `deletedAt`，释放 `dedupeScope`。
2. 删除这张照片的所有 `AlbumMedia` 关联；如果它是相册封面，清空封面。
3. 清空指向它的记录封面、旅行封面、用户头像、家庭档案头像和物品照片字段，避免页面出现打不开的图。
4. **保留** `EntryMedia`、`TripVisitPhoto` 和 `MediaTag` 关联。记录详情和旅行页面本来就会过滤非 `ACTIVE` 媒体，所以照片会从这些页面消失；恢复后关联仍在，照片会回到原来的记录/到访里。

软删除不删除任何文件。被取消的新上传（`DELETE /api/media/:id`）如果没有业务引用，会直接走下面的彻底删除；一旦有任何引用，也只做软删除。

## 恢复

回收站里的“恢复”会把 `status` 改回 `ACTIVE`。恢复前会先检查原图是否仍存在：如果彻底删除中途失败导致原图已经缺失，恢复会被拒绝，避免把一条打不开的记录放回照片墙。

恢复不会重新占用去重唯一键（`dedupeScope` 保持 `null`）。删除期间如果又上传了同内容图片，两张会同时存在，不会错误复用旧记录。相册关联也不会自动恢复，需要重新加入相册。

## 彻底删除

只有**已软删除**且没有任何业务引用的照片才能彻底删除。引用包括：

- 记录正文里的照片（`EntryMedia`）
- 相册关联（`AlbumMedia`）
- 旅行到访照片（`TripVisitPhoto`）
- 记录 / 相册 / 旅行封面
- 用户头像、家庭档案头像
- 物品照片

`MediaTag` 属于媒体自己的标签，会随媒体一起删除，不阻止清理。

清理顺序：

1. 再次检查引用；有引用就拒绝，并说明被多少条记录/相册/到访/头像/物品/封面引用。
2. 按原图 → 缩略图 → 展示图 → 播放版的顺序调用存储后端删除。
3. 任一文件删除失败：保留数据库行，写入 `Media.purgeError` 和 `purgeAttemptedAt`，同时输出服务端错误日志；用户可以在回收站重试。
4. 全部成功后再删除 `Media` 行，标签关联随之级联删除。

已经不存在（例如上次清理已删掉）的文件视为成功，所以重试是幂等的。被引用的照片如果用户无法在界面里解除引用（例如旧记录里的照片），就会一直留在回收站，这是有意的保护，不允许绕过引用检查直接删文件。

## 审计存储

```bash
npm run audit:media
```

脚本只读，不会删除或修改任何东西。它会：

- 汇总数据库里所有媒体记录的原图、缩略图、展示图和播放版键，以及议题附件；
- 按后端枚举实际对象（本地目录或 OSS 前缀）；
- 报告“数据库有记录但文件缺失”和“存储里有文件但数据库无引用”的孤儿。
- 检查数据库中出现过的后端，并额外检查当前活动后端和本地存储。

退出码为 `1` 表示发现问题，`0` 表示一致。输出最多展示每类 20 条样例。

注意事项：

- 上传或彻底删除正在进行时，原图可能已经写入但数据库行还没建好，审计会短暂报告孤儿。建议在低峰期或停止写入后运行，隔几分钟再跑一次确认。
- OSS 审计会列出配置前缀下的全部对象，对象很多时耗时和请求量随对象数增长；只读，不会产生写操作。
- 脚本不会自动清理孤儿。确认文件确实不再被任何数据引用后，再人工处理；不要用脚本直接批量删除 `storage/`。

## 备份与恢复

- 本地存储的备份会包含软删除照片的文件（它们仍在 `storage/` 里）。彻底删除后的文件不会出现在之后的备份中。
- 使用 OSS 时，`npm run backup` 只备份数据库；OSS 对象需要版本控制或跨区域复制。数据库里仍保留 OSS 键，所以恢复数据库后需要确保对应 OSS 对象还在。
- 彻底删除是永久操作。删除前的备份仍可恢复那批文件；恢复后建议运行一次 `npm run audit:media`，确认数据库和存储一致。
- 相册、记录、旅行的删除不会删除媒体文件：相册只删除关联，记录进入回收站，旅行删除只级联旅行自己的数据。

## 已知边界

- 引用检查和文件清理之间有一个很短的窗口。正常界面不会在这时新建对 `DELETED` 媒体的引用，但直接改数据库或长时间打开旧表单仍可能造成竞争；清理前会再检查一次。
- 本地存储和 OSS 都用同一个逻辑键格式；如果手工改过 `storageDriver` 或移动过文件，审计会如实报告缺失，不会猜测文件位置。
- 彻底删除不会回收同一内容在其他媒体行里的副本；去重只保证上传时复用，不做跨行合并。
